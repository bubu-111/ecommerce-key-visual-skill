# 版式骨架库（五副起手骨架）

每个方向提案时绑定一副骨架；制作时按绑定骨架改写模板 `assets/main-image-template.html` 里 `.layout` 那一层的排布（本库说的「版式骨架」在模板中就是 `.layout` 块）——**骨架决定"东西放在哪"，配色和字体决定"东西长什么样"，两者独立**。只换配色或字体、不改骨架，不算换了方向。**反过来也一样：只给骨架不给配色/氛围，用户在"视觉风格"上就没得选**——方向提案须**两栏都给**（版式＝骨架编号＋构图差异；视觉风格＝3–5 个色值＋氛围词＋光感/材质）。

本骨架库是起手参考，不是封闭清单：商品与品牌资料指向别的排布时，按资料来做并声明；改出来的排布须同样通过安全区、300px 可读性与导出审计检查。

## 五副骨架一览

| 编号 | 名字 | 构图一句话 | 常配方向类型 | 适用画幅 |
| --- | --- | --- | --- | --- |
| A | 左文右图 | 文字列在左、商品列在右，纵向层级一眼到底 | 产品即英雄、常规主图 | 竖版、正方 |
| B | 居中对称 | 全部居中：标题压顶、商品居中占中、价格收底 | 简洁大气、仪式感 | 正方、竖版 |
| C | 上下横幅 | 上满幅商品/场景、下信息条 | 场景感、生活方式 | 横版、方版 |
| D | 对角动势 | 商品偏居一角、文字压另一角，背景线制造动感 | 性能感、科技感 | 竖版、方版 |
| E | 价格区块前置 | 价格/优惠做成大色块置顶或置底，商品次之 | 大促、预售 | 竖版、方版 |

## 三方向小样对比（提案时给用户看的图）

**方向提案要给的是「小样对比图」——三个方向各渲染一张缩略小样，并排给用户看。** 只写"骨架 A：左文右图"这类文字，用户得先在脑子里把它翻译成画面才能比较；多数人不会翻译，于是"选方向"退化成"挑配色"。

**怎么做**（五条硬要求，缺一条视为没给图）：

1. **并排三张，同尺寸同缩放比**——一张大一张小会让"大小"本身误导判断；
2. **每张小样用上该方向的真实色值**（背景、主色、文字色都按提案色值来），否则比不出风格差异；
3. **每张小样用上该方向绑定的骨架**（左右分栏／上下横幅／对角动势等），否则比不出版式差异；
4. **商品位放真实抠底素材的缩略**；素材未处理完可用等比例占位块，但须在图注标明"商品为占位"；
5. **每张下方标注**：方向名／骨架编号／该方向色值。

**呈现与落盘**：先在对话里内联呈现（可视化卡片／HTML 预览），让用户当场就能比；同时导出一张 PNG 存进项目目录、列入交付物，会话结束后仍可回查。

> **为什么不用字符线框代替**：线框只能说明"东西放在哪"，说明不了"配色放在一起是什么感觉"。用户挑方向时，配色带来的第一印象往往比版式更强——这正是必须渲染小样、而不是贴字符框的原因。

**确有渲染能力时退回字符框，视为未给图**（见 `SKILL.md` 工作流 2）。下面「骨架速查」里的字符线框仅用于**无浏览器、无绘图工具**的降级环境，且须标注"此为线框示意，非成品效果"。

## 骨架速查（字符线框·兜底）

**仅在无法渲染任何图形时使用**（无浏览器、无绘图工具）。此时把下列线框图贴进提案，并注明"**此为线框示意，非成品效果**"，在记录里写明"本轮无渲染能力，已降级为线框"。

**画图四要素**（缺一就退回"看不见"）：①**区块名**（Logo／主标题／要点／价格／CTA／商品）；②**商品位及其占比约束**（如"高 ≥ 短边 55%"）；③**层级关系**（主标最大，画出来要能一眼比出谁大谁小）；④**跨画幅变体按实际比例画**——横版就画成横框，别拿竖版框糊弄，并在图注里写明"骨架 X 的〈横版／竖版〉变体"。

## 各骨架的改法（只在模板样式之后**追加覆盖**；`window.design` 不动）

以下 CSS 片段是**追加在后、覆盖基础样式**的规则，**不要替换掉模板里 `.layout` 原有的 `position:absolute;inset:var(--safe)`**：`.layout` 一旦失去定位与 `inset`，高度会退化为 `auto`，骨架 B/C/E 里的 `flex:1`（flex-basis:0）就会**塌成 0 高**，而机器审计只查"超画布"、查不出这种空白塌陷——改完必须看一眼成图。

**骨架 A（模板默认，不改）**：`.layout` 保持 `grid-template-columns:1fr 1fr`。

**骨架 B · 居中对称**：
```css
.layout{display:flex;flex-direction:column;align-items:center;text-align:center}
.copy{align-items:center;width:100%}
.logo{object-position:center}
ul{list-style:none;padding:0;display:flex;gap:2em;flex-wrap:wrap;justify-content:center}
.product{flex:1;min-height:0}
```
注意：卖点横排后每条要短，防一行挤爆；商品居中时上下留白要够。

**骨架 C · 上下横幅**（DOM 顺序不变，用 order 调换）：
```css
.layout{display:flex;flex-direction:column}
.product{order:-1;flex:1.3;min-height:0}
.copy{flex:1;min-height:0;justify-content:flex-start;width:100%}
```
注意：`.copy` 要补 `width:100%`，否则模板残留的 `align-items:center` 会把信息条收窄居中、不满幅；商品图自带完整背景或场景时才好看，抠底图悬在横幅上会显得空，需配代码/生成背景。

**骨架 D · 对角动势**：
```css
.layout{display:block}
.product{position:absolute;right:0;bottom:0;width:62%;height:62%}
.copy{position:absolute;left:0;top:0;width:60%}
```
注意：**商品本体保持原样，不旋转不变形**（原素材保护规则）；动感用商品摆放位置加背景装饰线（渐变条、几何形）实现。商品设为 **62% 宽／高** 是骨架 D 的设定尺寸，已高于全局硬下限（高度 ≥ 短边 55%、宽度 ≥ 画布宽 30%，见「横版适配·商品最小占位」），与全局一致。改绝对定位后**文字区与商品区可能重叠，机器审计不查重叠**——须人工看局部截图判有无非预期遮挡；**装饰线必须挂 `data-check`**（见 `SKILL.md` 制作·审计覆盖），挂上后越出画布会被审计抓成警告，不再静默裁掉。商品压角时确保主体轮廓不越安全区。

**骨架 E · 价格区块前置**：
```css
.layout{display:flex;flex-direction:column}
.offer{order:-1;align-self:flex-start;background:var(--primary);color:#fff;padding:.4em .8em;border-radius:8px}
.copy{width:100%}
.product{flex:1;min-height:0}
```
注意：`.copy` 补 `width:100%` 防信息区收窄；`order` 作用于 `.copy` 内部——效果是价格块提到文字列最前（视觉落在画布顶部）。**要价格置底时**，`order` 做不到（它只在自己的父级里排序），直接在 DOM 里把 offer/conditions/cta 三个元素移到商品块之后。价格块放大后，主标题仍是信息层级参照（可按方向把价格放在层级首位，但块高不宜超过画布 1/4）；促销感与品牌调性的张力要在验收时单独核。

## 横版适配（16:9、16:10 等宽画幅）

上方一览表中 A/B/D/E 的适用画幅标注为竖版、正方，骨架 C 虽标横版、但自述「抠底图悬在横幅上会显得空」。**横版＋抠底商品图是常见组合**（店铺 banner、信息流、广告横幅），本库原来在这个组合上没有可直接照做的指引，故补本节：

- **商品最小占位（全骨架／全画幅硬下限，先定调）**：商品主体在成图里**高度 ≥ 画布短边的 55%、宽度 ≥ 画布宽的 30%**——这是**硬下限**，任何骨架、任何画幅都适用，低于此值即视为商品过小，须换骨架或重排（与「裁边后按新边界重算容器」是同一件事，见工作流 1）。横版另有**高度 ≤ 短边 60%** 上限（防信息条被挤爆，见下方「文案列高度硬上限」）；**55% ≤ 高度 ≤ 60%、宽度 ≥ 30%** 是横版的合规定区间。骨架 D 把商品设为 62% 宽／高，那是骨架 D 的设定尺寸，已**高于**全局硬下限（62% ≥ 55%、62% ≥ 30%），与本条一致；骨架 D 用于竖版／方版，不受横版 60% 上限约束。

- **推荐起手：用骨架 A 的横版变体**（左文右图在横版上最稳）：
  ```css
  .layout{display:grid;grid-template-columns:46% 1fr;align-items:center;gap:4%}
  .copy{min-width:0}
  .product{width:100%;height:100%;min-width:0;min-height:0;display:flex;align-items:center;justify-content:center}
  .product img{max-width:100%;max-height:100%;object-fit:contain}
  ```
  要点：文字列 **42–48%**、商品列 **52–58%**；横版纵向空间小，**卖点条数 ≤4** 且每条要短；商品列内**产品最小占位——高度 ≥ 画布短边的 55%、宽度 ≥ 画布宽的 30%**（全骨架硬下限，见上方「商品最小占位」；低于此值商品过小，须换骨架或重排）。
- **商品足迹的核验方法**：不要用"成图 vs 无商品对照图的像素差"测占比——**低对比主体会被系统性低估**（白色机身叠浅色墙面时，像素差测得的轮廓比真实渲染框少 5–6%，会误判"未达 55%"）。正确做法：**用与素材同像素尺寸的纯色替身图渲染一张对照图，与无商品版相减取 bbox**，得到精确渲染框；测得的高/宽再对照上面的最小占位约束。
- **商品高度有天花板**：横版下商品带每加高一分，信息条就矮一分——实测 16:9 画布商品带到约 58% 高时，信息条只剩约 30% 高度，英文内容已接近占满。**放大商品前先算信息条所需高度**（各语种取所需最大者），两边顶住了就改更小字级或两行信息条，不要硬塞——塞爆的表现是英文条件小字被裁或挤出画布。
- **文案列高度硬上限（防塞爆）**：横版下**文案列（信息条）高度 ≤ 画布高 × 45%**；换算即**商品高度建议 ≤ 画布短边 × 60%**（两者之和为安全余量）。商品要超过此上限时，必须换骨架（如改竖版或骨架 B/C 居中/满幅），不要把文字条压到 45% 以下——压到极限的表现是英文条件小字被裁或挤出画布。
- **跨画幅使用必须声明**：把标注「竖版/正方」的骨架用在横版（或反过来），属本库标注之外的使用，**须在方向提案表与 HTML 注释里各写一句**「本方向使用骨架 X 的〈横版/竖版〉变体，理由：…」。**不声明即视为方案记录不全**——评审无法从成图判断它到底是「按资料改排布」还是「违规沿用默认骨架」。
- 骨架 C 用在横版时，抠底商品图须配代码/生成背景填底（见骨架 C 注意项），不要让它孤悬。
- 换画幅后仍按「使用判据」第 4 条复查：换行是否裁字、主体是否越安全区、300px 缩略图层级是否还读得出。

## 参考图技法的适用前提与替代

案例库里的参考图用了一些技法，但并非都能无条件照搬——它们有**适用前提**，前提不满足时要**换替代技法**，而不是硬上或干脆跳过：

- **引线标注（用线指向商品某部件写说明）**：前提是**有部件坐标素材**（能精确指出「这是吸口／那是滤网」）。没有坐标时不可用——乱指会指错位置、误导。替代：用「部件文字说明列」，在信息区把「部件 → 对应卖点」列点说明，不画线。
- **满版暗调（整张暗背景烘托）**：前提是**有浅色版 Logo，或品牌允许改色**。Logo 只有深色版时不可用——暗底上深色 Logo 看不见。替代：用**半透明深色蒙层（`rgba(0,0,0,.35)`）覆盖背景**＋对 Logo 加**浅色描边／发光**（`filter:drop-shadow(0 0 6px rgba(255,255,255,.6))`），使深色 Logo 在暗底仍可读。

这两条属**能力硬边界**，不是缺陷；在方向提案与验收时如实标注「本任务未采用某技法，因前提不满足（改用了替代）」，比硬上更符合「原素材保护／品牌可识别」规则。

## 使用判据

1. **各方向必须绑定不同的骨架**；提案表里每方向写明骨架编号＋一句话构图差异。用户指定方向数量时按用户数量（不强凑三份），但**方向之间仍不得共用同一副骨架**。
2. **每个方向还要同时给出「视觉风格」栏**（3–5 个具体色值＋氛围词＋光感/材质描述）——只写"治愈系"这类形容词不算。**骨架决定"东西放在哪"，视觉风格决定"看起来是什么调性"，两栏缺一不算一个可用方向**；两个方向色值高度重合，等于用户在风格上没得选。
3. **选定方向后按绑定骨架起手**，不得中途悄悄换回骨架 A；确需换骨架时回到 G3 说明理由并留痕。
4. 换骨架后必查：换行是否裁字、主体是否越安全区、300px 缩略图层级是否还读得出；机器警告按主文件口径逐条判「未裁切／确有缺陷／未确认」，不以"告警清零"为通过条件。
5. 多语言版本沿用同一副骨架（同一件商品的语种之间，版式一致，或仅做换行、字号与必要的局部版式适配）。
