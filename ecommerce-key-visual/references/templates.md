# 工作与评估记录模板

按实际任务填写。同一事实不重复抄写来源与确认状态；它同时属于两类时，在两类各登记一行并指向同一来源（见下）。简单任务可合并表格。未知写未知，未做的检查写未验证。

## 素材台账

「输入项」按实际收到的单位登记：一个文件算一行，一整段文字也算一行。未采用的必须写原因。

**默认素材为透明 PNG**；若文件名与真实格式／内容不符（异常），照常登记并标出——核对「文件名后缀 ↔ 真实格式 ↔ 实际内容」三者，不一致就在「格式/尺寸/透明度与边缘结论」列写明（如"文件名 .png，实为无透明通道的实心图"），**照常使用**，不停工、也不要求对方重命名。抠底图一并登记**裁前／裁后尺寸**（见工作流 1 的裁透明边规则）。

## 模板字段 ↔ 记录对应（`assets/main-image-template.html` 的 `window.design`）

改模板前先对照本表取值，避免图上写的和台账对不上。

| 模板字段 | 取自哪里 | 注意 |
| --- | --- | --- |
| `width`／`height`／`safe`／`maxBytes` | 规格记录：宽×高、四边安全区、体积上限 | 须与导出命令的宽高一致；无依据时用默认 800×800、安全区取短边 5% 并声明 |
| `colors.primary`／`ink`／`bg` | 事实表·品牌约束（色值） | 无品牌规范时标"临时视觉方案"，不写成官方规范 |
| `font` | 事实表·品牌约束（字体） | 实际与替代字体写进验收记录的环境预检栏；字体变化后重查换行 |
| `productImage`／`logoImage`／`backgroundImage` | 素材台账：文件、角色、使用位置 | 商品与 Logo 必须是原素材；背景可为生成图或代码 |
| `versions.<语种键>.brand`／`.name`／`.cta` | 事实表·品牌名、商品名、行动引导（**三者都按语种各一份**） | 缺失时先问，不自拟。这三处最容易"只改一个语种就以为全改到了"；中英两版并排核这三处是语种核查第一步（六轮复现的"英文版品牌行混中文"就出在这里） |
| `versions.<语种键>.lang／headline／points／offer／conditions` | 事实与需求表对应字段：语种、核心价值、卖点、价格与活动条件 | 译文另记入"翻译/生成"对照表；价格与档期只能来自来源或用户确认 |

两点补充：**默认规格**（800×800、安全区取短边 5%）以 `SKILL.md`「输入与缺项处理·规格」为准，本表与 `references/platforms.md` 引用同一口径，改动须三处同步。**字号是自动缩放的**——模板按 `min(宽,高)/800` 等比派生 `--gap／--title／--body／--small／--price／--logo-h`，改画布尺寸后字距与字号会跟着变；需要精确控制时在页面里覆盖这些变量。

## 行长 → 字号 参考（英文长文本断行辅助）

英文长行（价格组合、条件说明、卖点）必须手动指定断点（见 `SKILL.md`「制作」），下表给出「单行最多 N 个英文/数字字符（行长）」对应的**基准字号**，用于选一个不会撑破安全区的字号起点。

- **基准**：画布短边 **1080**，安全区取短边 5%，可用文字宽 ≈ 1080 − 2×(5%×1080) = **972px**。下表「基准字号」即按 1080 短边给出。
- **缩放**：实际画布短边为 S 时，实际字号 = 基准字号 × (S / 1080)。**注意：模板内置的字号锚点（标题 48px × min(宽,高)/800）是"通用层级起点"，与下表不是同一套、数值不可互推**——英文长行选字号以下表为准，两处不一致时先按表定起点，再以实际渲染宽度复核（同一串在目标字体下的渲染宽度 ≤ 安全区宽）。
- **这是起点不是铁律**：最终以实际渲染宽度核对（同一串在目标字体下的渲染宽度 ≤ 安全区宽）。中英文/数字混排按实际字符宽度微调；等宽或窄体字体可上浮，宽体（如衬线）需下调。

| 单行最多字符数（行长） | 基准字号（1080 短边） | 适用举例 |
| --- | --- | --- |
| ≤ 8 | 140 | 大标题、极短标语 |
| 9–14 | 110 | 主标题 |
| 15–22 | 84 | 卖点短句 |
| 23–32 | 60 | 价格组合、条件短句 |
| 33–45 | 46 | 较长条件说明 |
| 46–60 | 36 | 多行说明、脚注 |

> 例：画布 1080×1920（短边 1080），行长 28 → 取 60；画布 800×800（短边 800），同行长 → 60 × (800/1080) ≈ 44。

## 方向与信息层级

方向**必须同时给出两栏，缺一不算方向**：

| 栏 | 填什么 | 必填字段 |
| --- | --- | --- |
| **版式** | 用骨架 A / B / C / D / E（见 `references/layouts.md`） | 骨架编号 ＋ 一句话构图差异 ＋ **渲染小样（三方向并排对比图里的那一张）** |
| **视觉风格** | 配色 / 氛围 / 材质 / 光感 | **3–5 个具体色值** ＋ 氛围词（如"奶油治愈""霓虹夜市"） ＋ 光感/材质描述 |

每个方向另写：概念/目标人群、核心视觉锚点、信息层级，以及与其他方向的差异。选择：方向及确认/授权依据（**笼统委托如「你来完成」「你来测试」不含方向；只有「获得方向授权」——指名授权，或用户已自行选定方向——才算授权**）。用户指定数量或方向时不强凑三份。**两个方向的色值高度重合时，等于没给出风格上的选择，须重做。**

**小样对比图是必填项，不是加分项**：骨架编号只是一个字母，用户看不出 A 和 C 的差别在哪，**也看不出配色放在一起是什么感觉**。三个方向各渲染一张缩略小样（用上该方向的骨架**与真实色值**），并排呈现；要求与做法见 `references/layouts.md`「三方向小样对比」。字符线框图只在无渲染能力时兜底，且须标注"非成品效果"——**有渲染能力却退回字符框，视为未给图**。

> **正误对照**：错——「方向 1：骨架 A，左文右图；方向 2：骨架 C，上下横幅」，两个字母加八个字，用户得自己在脑子里渲染一遍才能比；也错——在 md 里贴三张 `┌─┐` 字符框，那还是"描述版式"，不是"看到画面"；对——三张按真实色值与骨架渲染出来的缩略小样并排，商品位、主标层级、价格区块一眼可比。

**提案怎么递到用户面前**：方向写完后**在当前这一轮对话内发起交互选择并原地等待答复**，不得写完文件就结束回合——否则用户要另起一条消息重开，一次连贯任务被切成两段，且事后从产物上看不出是卡在 G3 还是已交付。交互方式与无交互能力时的降级写法见 `SKILL.md` 工作流 2「方向选择是中途交互」。

信息层级表用「信息类别」列强制分组——**同类可同行，异类必须分行**：

| 信息 | **信息类别** | 必需/可选 | 优先级与呈现条件 | 位置与缩略图阅读目标 |
| --- | --- | --- | --- | --- |

> **正误对照**：错——把"线上线下发售时间"与"常规款/隐藏款概率"排在**同一行**（两类信息挤一行，缩略图下读不出）；对——**概率一类自成一行/一段，发售一类自成一行/一段**，分组边界在表里看得见。

## 成品验收

本节的表格即**验收表**（空白模板）；填好后连同证据合称**验收记录**。

| 检查 | 结论：通过/失败/未验证 | 证据或具体问题 |
| --- | --- | --- |
| 输入文件盘点、提取正确且有来源（未分类资料拆解后已归类，无遗漏） | | |
| 每份输入的去向：已上图标明位置／未采用注明原因 | | |
| 必需信息与素材呈现完整；价格/单位/条件准确；无无依据新增；成图内容性元素逐一对上资料包素材或任务书文字（含：已被 Logo 表达的品牌名等不得另打文字） | | |
| 商品/Logo 外观保持；轮廓、结构、标识与接触处无非预期遮挡 | | |
| 元素空间关系（位置、尺寸、间距、对齐、重叠关系）与事实表／素材台账／方向方案一致 | | |
| 宽高、格式、体积、安全区，无占位/裁字 | | |
| 语种内容对应与排版适配 | | |
| 各语种版本号同步（同一轮迭代中英版号一致） | | |
| 同一含义的元素（标题/品牌/价格）在各语种下颜色、粗细、层级一致 | | |
| 压缩后的子事实清单在各语种对齐（某语种删减/合并的子事实已在验收记录写明） | | |
| 版式与 G3 所选方向绑定的骨架一致（未中途换回默认骨架） | | |
| 构图、字体、色彩、合成、品牌和传播目标；装饰/伪元素已复核 | | |
| 源码/资源齐全，可继续修改和导出 | | |

证据可用对照表、实际成图、300px 缩略图和机器检测结果，不强制每个字段都截图。成图打分与返工判据按 `references/quality-rubric.md`：把五个维度的**分数与理由、评分者**记在本节（可另起一小行，或写在证据/备注里）；无成图不得评分。**自评只是自检，不代替用户复核——是否通过仍由用户判定。** **本表与打分表的分工**：本表判"是否符合要求"（通过／失败／未验证），`quality-rubric.md` 的五维分数判"做到多好"；同一处问题可两边各记一次，不互相替代。

环境预检：渲染器/字体、启动与保存是否成功、输出尺寸、替代路径及阻塞。**字体须实测**——写「任务书指定字体 / 实际使用字体 / 判定方法（宽度比对或字体目录）/ 替代理由 / 许可状态」，**不许**只凭 `document.fonts.check()` 写"无替代"；字体缺失已问用户、用户选择替代或安装，也要记在这里。**开工前缺失工具清单与用户答复**也记在本栏。**机器警告栏**：对象、指标、**溢出像素数**、裁切条件、局部证据、人工结论（未裁切/确有缺陷/未确认）。

修复：旧版本、错误位置、根因、修改、新版本、尝试次数、复检结果；保留前后证据，不覆盖历史失败。仍失败：草稿状态、阻塞、所需输入或工具。
